# Using the shared sources in a Roslyn project

[DragoAnt.Roslyn.Shared.Sources](https://www.nuget.org/packages/DragoAnt.Roslyn.Shared.Sources) adds `.cs` files to the project that references it. This page shows how an analyzer, a source generator or a code fix references it, which parts each one gets, and how to work on the sources from a local checkout.

[DragoAnt.MSBuildKit](https://github.com/DragoAnt/MSBuildKit) will add the reference to every Roslyn project on its own from its next minor release; until then, add it by hand as below.

## Reference it

In the project of the analyzer, generator or code fix (not in the package that ships it to users):

```xml
<ItemGroup>
  <PackageReference Include="DragoAnt.Roslyn.Shared.Sources" Version="1.0.0" PrivateAssets="all" />
</ItemGroup>
<PropertyGroup>
  <!-- Common is always compiled; add Generators or CodeFixes for those roles. -->
  <DragoAntRoslynSharedParts>Common;CodeFixes</DragoAntRoslynSharedParts>
</PropertyGroup>
```

`PrivateAssets="all"` keeps the reference out of your package: an analyzer package built this way declares no dependency on it, and a project that uses your analyzer never restores it. The package is marked as a [development dependency](https://learn.microsoft.com/nuget/reference/nuspec#developmentdependency); keep the attribute on the reference either way.

| Role | `DragoAntRoslynSharedParts` | Compiled in |
| --- | --- | --- |
| Analyzer | `Common` | `SyntaxHelpers`, `LocationHelpers`, `DiagnosticHelpers` |
| Source generator | `Common;Generators` | the above and `EquatableArray<T>` |
| Code fix | `Common;CodeFixes` | the above and `LiteralRewriter` (it needs [Microsoft.CodeAnalysis.CSharp.Workspaces](https://www.nuget.org/packages/Microsoft.CodeAnalysis.CSharp.Workspaces), which only a code fix references) |

The property may be set anywhere in the project's evaluation — the csproj, `Directory.Build.props` or `Directory.Build.targets` — because the package reads it when it adds its items. An unknown part name raises warning `DARS001`.

The project must reference [Microsoft.CodeAnalysis.CSharp](https://www.nuget.org/packages/Microsoft.CodeAnalysis.CSharp) 5.0.0 or later and may target `netstandard2.0`.

## What you see in the IDE

The files are linked under `.da.shared/<Part>/` in Solution Explorer. They live in the NuGet package cache, shared by every project on the machine that uses the same version, so the first line of each file says not to edit it.

That line is also `// <auto-generated/>`. The compiler and analyzers treat the file as generated code:

- your own code-style and quality rules (an `IDExxxx` preference, a `CAxxxx` rule, an `.editorconfig` or `.globalconfig` severity) do not report on code you cannot change;
- the [banned-API rules for analyzers](https://github.com/dotnet/roslyn-analyzers/blob/main/docs/rules/RS1035.md) (`RS1035`) still run on it, because they analyze generated code too;
- nullable analysis stays on: generated code starts with nullable disabled, so every file opens with `#nullable enable`.

## Why sources and not a helper assembly

A helper assembly packed next to each analyzer looks simpler, but the compiler loads one copy of a same-named assembly for all analyzer packages in a build: the highest version wins. An analyzer built against an older helper then runs on the newer one and fails with `AD0001` (a `MissingMethodException`) as soon as a member it uses changed. Compiled-in `internal` copies have no such coupling: each analyzer, generator and code fix keeps the helpers it was built with.

Two consequences:

- Do not grant `InternalsVisibleTo` from an analyzer to its code fix. Both carry an `internal` copy of the same types, and the code fix would see two (`CS0436`). Keep diagnostic ids as `public` constants in the analyzer.
- The package never adds a run-time dependency; nothing from it is loaded next to your analyzer.

## Work on the sources from a checkout

Point the package's targets at a local clone of [DragoAnt/Roslyn](https://github.com/DragoAnt/Roslyn) instead of the cache:

```xml
<PropertyGroup>
  <DragoAntRoslynSharedSourceRoot>../../Roslyn/src/DragoAnt.Roslyn.Shared.Sources/src/</DragoAntRoslynSharedSourceRoot>
</PropertyGroup>
```

The folder must hold `Common/`, and `Generators/` and `CodeFixes/` for those parts; a folder without `Common` raises warning `DARS002`. When a project imports the targets twice (the package and a checkout copy), only the first import adds items.

## Properties

| Property | Default | Meaning |
| --- | --- | --- |
| `DragoAntRoslynSharedParts` | empty (`Common` only) | `;`-separated parts: `Common`, `Generators`, `CodeFixes` |
| `DragoAntRoslynSharedSourceRoot` | the package's `src/` | the folder the parts are compiled from |
